# T2：前端看板（owner：同事 A）

## 背景
实现技术债看板单页应用。开发期后端可能还没合并，**先连 Prism mock（:4010）开发**。

## 验收标准（可判定）
- [ ] 三列看板：待处理 / 处理中 / 已解决，列头显示该列数量
- [ ] 顶部新增表单：标题（必填）、描述、模块、严重度（P0/P1/P2 下拉）
- [ ] 卡片内容：标题、严重度色标（P0 红 / P1 黄 / P2 灰）、模块标签、描述（可选显示）
- [ ] 卡片操作："开始处理"（todo→doing）/"标记解决"（doing→done）/"删除"（带确认）
- [ ] 操作后列表即时刷新，统计条同步更新
- [ ] 筛选：按模块（下拉去重）、按严重度
- [ ] **刷新浏览器后状态保持**（数据来自 API，不是纯内存）
- [ ] 当 `VITE_API_BASE` 为空时，用内置 3 条假数据也能完整演示（不连后端）

## 范围
- 只写 `frontend/` 目录
- **不做**：路由多页面、登录、单元测试、UI 组件库

## 契约
`docs/contracts/openapi.yaml` v1.0。类型定义 `src/api/types.ts` 必须与契约字段一致（snake_case）。

## 约束
- 不新增 UI 依赖（react/react-dom 之外）
- 组件内禁止裸 `fetch`，必须走 `src/api/client.ts`
- 样式手写 CSS，深色背景卡片式布局（参考 Trello 风格）

## AI 使用说明
- 组件骨架 / 样式：AI 生成
- 状态流转逻辑、筛选逻辑：人工核对
- 类型定义生成后，对照契约逐字段检查一遍
